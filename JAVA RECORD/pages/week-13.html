Task 1: Derived and Custom Query Methods in Spring Data JPA

🎯 1. Aim

To design, implement, and verify all 8 prescribed derived and custom query methods in Spring Data JPA, evaluating repository method naming conventions, JPQL abstractions, and native SQL execution via @Query:

  • findAll() — Retrieving all student records.
  • findByName(String name) — Exact match on name property.
  • findByFirstName(String firstName) — Single field predicate lookup.
  • findByFirstNameAndLastName(String fn, String ln) — Conjunctive AND condition.
  • findByFirstNameOrLastName(String fn, String ln) — Disjunctive OR condition.
  • findByLastNameOrderByFirstNameAsc(String ln) — Ordered criteria sorting.
  • findFirst10ByLastName(String ln) — Query result set limiting.
  • @Query(nativeQuery = true) fetchByFirstName() — Custom native SQL execution.

⚙️ 2. Software Requirements

💻 Development Stack
IDE: Spring Tool Suite 4
Framework: Spring Data JPA 3.x with Hibernate ORM
Database: In-Memory H2 / Relational MySQL
Logging: logging.level.org.hibernate.SQL=DEBUG
🗄️ Query Derivation Grammar
Subject Keywords: find...By, read...By, get...By
Predicate Keywords: And, Or, OrderBy...Asc/Desc
Limiting Keywords: First<N>, Top<N>

☕ StudentRepository.java
package com.example.querydemo;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;
import org.springframework.stereotype.Repository;
import java.util.List;

@Repository
public interface StudentRepository extends JpaRepository<Student, Integer> {

    // 1. Retrieve all records
    List<Student> findAll();

    // 2. Exact match on name property
    List<Student> findByName(String name);

    // 3. Exact match on firstName
    List<Student> findByFirstName(String firstName);

    // 4. AND Condition on both names
    List<Student> findByFirstNameAndLastName(String firstName, String lastName);

    // 5. OR Condition
    List<Student> findByFirstNameOrLastName(String firstName, String lastName);

    // 6. Filter by lastName and ORDER BY firstName ASC
    List<Student> findByLastNameOrderByFirstNameAsc(String lastName);

    // 7. Top 10 limiting clause
    List<Student> findFirst10ByLastName(String lastName);

    // 8. Custom Native SQL query
    @Query(value = "SELECT * FROM student WHERE first_name = :fn", nativeQuery = true)
    List<Student> fetchByFirstName(@Param("fn") String fn);
}

📊 6. Result Analysis & Discussion

🔍 Abstract Syntax Tree (AST) Parsing

Spring Data JPA parses method identifiers using a recursive descent parser, stripping prefixes (findBy) and splitting keywords (And, Or, OrderBy) to compile an Abstract Syntax Tree (AST) translated directly into criteria queries.

⚡ Compile-Time Type Safety

If an entity property name is misspelled in the method signature (e.g. findByFristName), Spring Boot fails immediately during bean creation at application startup, eliminating silent runtime SQL syntax errors.

🛡️ SQL Injection Immunity with @Param

Both derived queries and @Query annotations utilize parameterized positional or named bindings (:fn), ensuring database drivers treat user inputs strictly as literal values rather than executable SQL commands.

💡 JPQL vs Native SQL Portability

Derived methods and JPQL target entity names and operate identically across H2, MySQL, Oracle, and PostgreSQL. Native queries (nativeQuery = true) bypass JPA abstraction to access vendor-specific database features (full-text search, window functions).
