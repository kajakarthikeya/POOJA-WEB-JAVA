Browser security restrictions and the deprecation of NPAPI (Netscape Plugin Application Programming Interface) eliminated client-side Java Applets. Server-side Java Servlets emerged as the standard, running within high-throughput web containers to serve dynamic HTTP content securely and scalably.

TASK 4 · DATABASE CONNECTIVITY ARCHITECTURE

Task 4: JDBC and ODBC

🔌 Database Connectivity: Type-4 Pure Java vs Type-1 ODBC Bridge

Open Database Connectivity (ODBC) requires native C/C++ libraries installed on each client machine. Java Database Connectivity (JDBC) Type-4 direct-socket network protocol drivers communicate directly with MySQL and Oracle databases over TCP/IP (port 3306), achieving cross-platform portability and zero native dependency overhead.

Feature ODBC (Open Database Connectivity) JDBC (Java Database Connectivity)
Origin Language C / C++ Native Binary API Pure Java Object-Oriented API (java.sql.*)
Platform Portability Platform dependent (Windows/Linux ODBC managers) 100% Platform independent (WORA: Write Once, Run Anywhere)
Driver Architecture Native DLLs and client OS middleware Type-4 Direct Network Socket Driver (mysql-connector-j)
Connection Pooling Managed via OS ODBC Administrator Integrated via HikariCP, Tomcat DBCP, and DataSource APIs
TASK 5 · STATE MANAGEMENT STRATEGIES

Task 5: Cookies and Sessions

🍪 HTTP State Tracking: Cookies vs Server-Side HttpSession

Because the HTTP protocol is inherently stateless, enterprise applications track user identity and state using either client-side HTTP Cookies or server-side HttpSession objects referenced by JSESSIONID tokens.

Criterion HTTP Cookies HttpSession
Storage Location Client browser text store (< 4 KB per cookie) Server heap memory (unlimited object graph size)
Data Type String / Text only (requires URL encoding) Any Serializable Java Object (java.lang.Object)
Security Context Vulnerable to client inspection & XSS without HttpOnly Secure: Client receives only transient opaque session ID
Lifecycle Management MaxAge attribute (persistent or session-scoped) session.setMaxInactiveInterval() or session.invalidate()

📊 6. Result Analysis & Discussion

C and C++ deliver unmatched raw CPU execution performance due to zero runtime VM overhead. Java approaches within 10-15% of C++ speed post-warmup due to HotSpot JIT C2 optimization and tiered compilation, while maintaining total OS portability.

🛡️ Memory Safety & Reliability

Manual memory management in C/C++ accounts for over 70% of production vulnerabilities (buffer overflows, dangling pointers, memory leaks). Java's automated managed memory and absence of pointer arithmetic guarantee rock-solid runtime memory safety.

⚡ Concurrency & Multithreading

Python's GIL (Global Interpreter Lock) severely limits CPU-bound multithreaded scaling on modern multicore servers. Java's native OS thread mapping and modern Project Loom Virtual Threads enable millions of concurrent operations with minimal footprint.

🏢 Enterprise Maintainability

Java's strict static typing, robust interfaces, and mature tooling (Maven, Gradle, Spring ecosystem) dramatically reduce refactoring risks in large teams, outperforming dynamic languages in multi-million-line codebases.

📊 6. Result Analysis & Discussion

🔍 Elimination of Native ODBC DSN Bridges

Legacy Type-1 JDBC-ODBC bridges were deprecated and permanently removed in Java 8. UCanAccess operates as a pure-Java Type-4 driver, translating JDBC requests into Jackcess memory structures, enabling seamless MS Access execution on non-Windows OS (Linux/macOS).

⚡ HSQLDB In-Memory Execution Architecture

UCanAccess loads MS Access .accdb binary tables into an internal embedded HSQLDB instance in RAM, evaluating complex SQL queries with high memory speed before committing modifications back to the disk file.

🛡️ Classpath Dependency Resolution

All five constituent JARs (ucanaccess, jackcess, hsqldb, commons-lang3, commons-logging) must be co-present in the classpath; missing a single logging or utility library triggers fatal NoClassDefFoundError exceptions.

💡 Concurrency & File Locking Findings

MS Access relies on file-level locks (.laccdb). UCanAccess maintains safe single-process locks, but high-concurrency multi-user write scenarios are vulnerable to lock contention compared to true client-server RDBMS engines (MySQL/PostgreSQL).

📊 6. Result Analysis & Discussion

🔍 ACID Transactional Mechanics

By default, JDBC operates in auto-commit = true mode, causing each DML query (UPDATE and DELETE) to be committed immediately to MySQL's InnoDB redo logs, ensuring durability at the cost of individual disk flushes.

⚡ Resource Leak Prevention & Finally Blocks

Failing to close database connections causes socket starvation in production, exhausting MySQL's max_connections limit. Wrapping cleanup inside a finally block or try-with-resources guarantees socket destruction even under exceptions.

🛡️ Row Locking & Isolation Levels

MySQL InnoDB acquires an exclusive row lock (X-lock) during UPDATE and DELETE. Explicit connection teardown releases locks immediately, preventing deadlock scenarios across concurrent database clients.

💡 DML Mutation Verification

Checking the integer return value from stmt.executeUpdate() validates whether the target record was matched by the WHERE clause, differentiating zero-row matches from operational database failures.

📊 10. Result Analysis & Discussion

🔍 Servlet Dispatch Pipeline & Thread Safety

Tomcat instantiates only a single servlet instance per registered class in memory, spawning lightweight worker threads per incoming HTTP socket. Because instance variables are shared across concurrent requests, servlets must remain strictly stateless to guarantee thread safety.

⚡ GenericServlet vs HttpServlet Routing Overhead

HttpServlet.service() inspects request.getMethod() to dynamically route traffic to doGet(), doPost(), doPut(), or doDelete(). GenericServlet avoids HTTP header parsing, delivering minimal overhead for raw socket stream protocols.

🛡️ HTTP GET vs POST Payload Security

GET requests append form data into plaintext URL query strings subject to server access log leakage and browser history exposure. POST packages form bodies into HTTP message payloads, enabling transmission of large payloads without URI length limits.

💡 Lifecycle Hooks & Resource Teardown

init() executes exactly once during servlet class loading (or eagerly via <load-on-startup>) to initialize database connection pools. destroy() triggers during server shutdown to gracefully flush caches and close open file descriptors.

package com.example.jdbch2demo;

import jakarta.annotation.PostConstruct;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Service;
import java.util.Arrays;
import java.util.List;

@Service
public class AuthorService {
    private static final Logger log = LoggerFactory.getLogger(AuthorService.class);
    private final JdbcTemplate jdbcTemplate;

    public AuthorService(JdbcTemplate jdbcTemplate) {
        this.jdbcTemplate = jdbcTemplate;
    }

    @PostConstruct
    public void init() {
        log.info("Creating tables...");
        jdbcTemplate.execute("DROP TABLE IF EXISTS author");
        jdbcTemplate.execute("CREATE TABLE author(id SERIAL, name VARCHAR(255), genre VARCHAR(255))");

        List<Object[]> authors = Arrays.asList(
            new Object[]{"J.K. Rowling", "Fantasy"},
            new Object[]{"George R.R. Martin", "Epic Fantasy"},
            new Object[]{"Agatha Christie", "Mystery"}
        );

        jdbcTemplate.batchUpdate("INSERT INTO author(name, genre) VALUES (?,?)", authors);
        log.info("Batch insert completed successfully.");
    }
}

📊 6. Result Analysis & Discussion

🔍 Boilerplate Elimination via JdbcTemplate

Traditional JDBC requires manual connection opening, statement preparation, ResultSet loop traversal, and nested try-catch blocks. Spring's JdbcTemplate encapsulates this entire boilerplate, automating resource cleanup and connection release.

⚡ High-Throughput Batch Operations

batchUpdate() executes multiple DML statements in a single round-trip over the database socket, avoiding per-row network latency and dramatically accelerating bulk insert performance.

🛡️ DataAccessException Translation

Spring intercepts checked SQLException instances and translates them into an expressive, unchecked DataAccessException hierarchy, decoupling business services from vendor-specific SQL error codes.

💡 Ephemeral In-Memory Lifecycle

jdbc:h2:mem:testdb exists strictly inside JVM heap memory and evaporates upon JVM shutdown, making it the ideal zero-dependency database for rapid integration testing and automated CI/CD pipelines.

📊 6. Result Analysis & Discussion

Hibernate ORM bridges the fundamental paradigm gap between object-oriented Java concepts (encapsulation, polymorphism) and relational tabular models (primary keys, foreign keys) without manual SQL string concatenations.

Spring Boot 3 uses HikariCP by default. Its bytecode-level optimization and lightweight connection leasing reduce database connection acquisition overhead to microseconds.

spring.jpa.hibernate.ddl-auto=update allows Hibernate to automatically detect newly added entity fields and alter MySQL tables without dropping existing production rows.

💡 Server-Side Template Processing

Thymeleaf executes entirely on the server during the HTTP response cycle, injecting database collections into HTML attributes (th:each="emp : ${employees}"), delivering fast initial page loads and strong SEO friendliness.

package com.example.querydemo;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;

import java.util.List;

@Repository
public interface StudentRepository extends JpaRepository<Student, Integer> {

    // 1. Retrieve all records
    List<Student> findAll();

    // 2. Exact match on name property
    List<Student> findByName(String name);

    // 3. Exact match on firstName
    List<Student> findByFirstName(String firstName);

    // 4. AND Condition on both names
    List<Student> findByFirstNameAndLastName(String firstName, String lastName);

    // 5. OR Condition
    List<Student> findByFirstNameOrLastName(String firstName, String lastName);

    // 6. Filter by lastName and ORDER BY firstName ASC
    List<Student> findByLastNameOrderByFirstNameAsc(String lastName);

    // 7. Top 10 limiting clause
    List<Student> findFirst10ByLastName(String lastName);

    // 8. Custom Native SQL query
    @Query(value = "SELECT * FROM student WHERE first_name = :fn", nativeQuery = true)
    List<Student> fetchByFirstName(@Param("fn") String fn);
}

📊 6. Result Analysis & Discussion

🔍 Abstract Syntax Tree (AST) Parsing

Spring Data JPA parses method identifiers using a recursive descent parser, stripping prefixes (findBy) and splitting keywords (And, Or, OrderBy) to compile an Abstract Syntax Tree (AST) translated directly into criteria queries.

⚡ Compile-Time Type Safety

If an entity property name is misspelled in the method signature (e.g. findByFristName), Spring Boot fails immediately during bean creation at application startup, eliminating silent runtime SQL syntax errors.

🛡️ SQL Injection Immunity with @Param

Both derived queries and @Query annotations utilize parameterized positional or named bindings (:fn), ensuring database drivers treat user inputs strictly as literal values rather than executable SQL commands.

💡 JPQL vs Native SQL Portability

Derived methods and JPQL target entity names and operate identically across H2, MySQL, Oracle, and PostgreSQL. Native queries (nativeQuery = true) bypass JPA abstraction to access vendor-specific database features (full-text search, window functions).
